# EnerPrice 2.6.7 — Home Assistant event-loop compatibility / Compatibiliteit met Home Assistant-eventloop

## English

### Fixed
- Initialize the Europe/Amsterdam timezone once at module import instead of constructing it for the first time inside asynchronous Energy Charts and ENTSO-E price provider methods.
- Reuse the same timezone object when interpreting Energy Charts timestamps.
- Address the event-loop blocking concern raised during the HACS default-repository review ([hacs/default#11476](https://github.com/hacs/default/pull/11476)).

### Update and verify
1. Update EnerPrice to **2.6.7** through HACS and restart Home Assistant.
2. Check that your price sensors still update as expected. The price calculations and configuration are not intended to change.
3. If an issue occurs, include relevant Home Assistant logs in a GitHub issue.

---

## Nederlands

### Opgelost
- De tijdzone Europe/Amsterdam wordt nu eenmalig bij het laden van de module aangemaakt, niet meer voor het eerst binnen asynchrone prijsproviderfuncties voor Energy Charts en ENTSO-E.
- Dezelfde tijdzone wordt ook gebruikt bij het interpreteren van Energy Charts-tijdstempels.
- Hiermee wordt het mogelijke blokkeren van de Home Assistant-eventloop aangepakt dat tijdens de HACS-beoordeling is gesignaleerd ([hacs/default#11476](https://github.com/hacs/default/pull/11476)).

### Bijwerken en controleren
1. Werk EnerPrice via HACS bij naar **2.6.7** en herstart Home Assistant.
2. Controleer of de prijssensoren normaal blijven bijwerken. De prijsberekeningen en instellingen zijn niet bedoeld te veranderen.
3. Meld eventuele problemen via GitHub Issues, met relevante Home Assistant-logregels.

---

**Compatibility / Compatibiliteit:** Existing configuration and entity IDs remain unchanged. / Bestaande instellingen en entiteits-ID's blijven ongewijzigd.
